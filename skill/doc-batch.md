# 深鲸文档批量处理（dsh-doc-batch）

一个入口处理三类文档，命令统一为 `dsh-doc-batch <格式> <操作> --input <路径>`：

- `docx`（别名 `word`）：替换 / 提取正文 / 合并 / 页眉页脚 / 转 Markdown
- `xlsx`（别名 `excel`）：合并 / 清洗 / 列汇总 / 导出 CSV
- `pdf`：合并 / 拆分 / 压缩 / 水印 / 提取文本 / 提取图片

面板（侧栏「深鲸文档批量」）与 CLI 是同一套能力：选格式 → 选操作 → 填路径 → 开始处理。
所有处理都在本机完成，不上传文件。

需要 `python3` 与对应库：python-docx / openpyxl / pypdf。


---

## Word（docx）

# Word 批量处理

**一句话**：整目录的 Word 一次处理完 —— 批量替换文本、提取正文、按文件名合并、列页眉页脚、转 Markdown。只读输入，产物单独输出，不覆盖原文件。

## 什么时候用

用户说这些话时用：

- 「把这批 Word 里的××全部改成××」「50 份合同批量替换甲方」
- 「把目录下这些 docx 合并成一份」「周报合成一个文件」
- 「把这些 Word 的正文提取成 txt」「把 Word 转成 Markdown」
- 「看看这些文档的页眉页脚都写了什么」
- 用户给了一个装了很多 `.docx` 的目录，要求批量处理其中文字

## 怎么调用

```bash
<cli 路径> --help
```

```bash
# 批量替换（--from/--to 可多组，按顺序配对；改正文、表格、页眉页脚）
<cli 路径> replace --input <文件或目录> [--out <输出目录>] \
  --from 旧文本 --to 新文本 [--from 旧2 --to 新2] [--json]

# 提取正文到 .txt
<cli 路径> extract --input <文件或目录> [--out <输出目录>] [--json]

# 按文件名自然顺序合并
<cli 路径> merge --input <文件或目录> [--out <输出目录>] [--json]

# 列出页眉页脚
<cli 路径> headers --input <文件或目录> [--out <输出目录>] [--json]

# 转 Markdown
<cli 路径> to-md --input <文件或目录> [--out <输出目录>] [--json]

# 自造样例跑完整流程（不碰用户文件），推荐先跑这个确认环境正常
<cli 路径> --demo
```

## 输出约定（要向用户说清）

- **不修改输入文件**；输出默认写到 `<输入目录>/_输出`，可用 `--out` 指定。
- 同名产物不覆盖：自动变成 `合同_1.docx`、`合同_2.docx`。
- 目录递归处理，跳过 `~$` 临时文件和 `_输出` 目录。
- 成功退出码 0；参数/输入错误退出码 2；缺依赖退出码 3；运行失败退出码 1。
- `--json` 时输出结构化结果（含每个文件的产物路径和替换次数 / 字符数等）。

## 边界（必须向用户说清）

- **替换可能影响局部格式**：跨多个 run 的匹配会合并段落内的 run，局部加粗/字号/颜色可能丢失。
  重要文档先小批量跑一份对比，再整目录处理。
- 只支持 `.docx`；`.doc` 老格式、`.docm`、加密文档不支持，需先另存为 `.docx`。
- 只覆盖正文段落、表格、页眉页脚；**不处理**脚注、尾注、批注、文本框、SmartArt、图片里的文字。
- `merge` 只合并正文与表格，不合并页眉页脚和样式主题；复杂排版会退化为顺序文本。
- `headers` 只读不改；替换是字面匹配，大小写敏感，不支持正则。
- 缺 `python3` 或 `python-docx` 时会明确打印安装命令（`python3 -m pip install python-docx`），不会静默失败。
- 不联网、不上传文档，全部在本机处理。

## Excel（xlsx）

# Excel 批量处理

**一句话**：整目录的 Excel 一次处理完 —— 多文件多 sheet 合并、删空行去重 trim、列级汇总、每个 sheet 导出 CSV。只读原表，产物单独输出，不覆盖原文件。

## 什么时候用

用户说这些话时用：

- 「把这些门店表 / 周报合并成一张总表」「多个 sheet 合成一个」
- 「去掉表格里的空行、重复行、姓名前后的空格」
- 「统计每列有多少非空、金额合计多少」
- 「把每个 sheet 导出成 CSV」「Excel 转 CSV」
- 用户给了一个装了很多 `.xlsx` 的目录，要求批量整理、汇总或导出

## 怎么调用

```bash
<cli 路径> --help
```

```bash
# 多文件 / 多 sheet 合并（自动加「来源文件」「来源工作表」列，按表头名对齐）
<cli 路径> merge --input <文件或目录> [--out <输出目录>] [--json]

# 删空行、去重、trim 文本（保留所有 sheet）
<cli 路径> clean --input <文件或目录> [--out <输出目录>] [--json]

# 每列非空计数 / 数值列求和，导出报告
<cli 路径> summary --input <文件或目录> [--out <输出目录>] [--json]

# 每个 sheet 导出 CSV
<cli 路径> csv --input <文件或目录> [--out <输出目录>] [--json]

# 自造样例跑完整流程（不碰用户文件），推荐先跑这个确认环境正常
<cli 路径> --demo
```

## 输出约定（要向用户说清）

- **不修改输入文件**；输出默认写到 `<输入目录>/_输出`，可用 `--out` 指定。
- 同名产物不覆盖：自动变成 `merged_1.xlsx`、`merged_2.xlsx`。
- 目录递归处理，跳过 `~$` 临时文件和 `_输出` 目录。
- 导出 CSV 用 UTF-8 带 BOM，Excel 双击打开不乱码；文件名格式 `<工作簿名>__<sheet名>.csv`。
- 成功退出码 0；参数/输入错误退出码 2；缺依赖退出码 3；运行失败退出码 1。
- `--json` 时输出结构化结果（含删空行数、去重数、trim 数、汇总行数等）。

## 边界（必须向用户说清）

- **读的是值，不是公式**：公式取 Excel 上次保存时缓存的结果；没缓存过的公式可能读成空。
- 输出文件是**值**：公式、条件格式、图表、数据透视表、宏、原表配色/列宽/合并单元格**都不保留**，
  只保留基础格式（表头加粗、冻结首行）。
- 只支持 `.xlsx` / `.xlsm`；`.xls` 老格式、加密/密码保护的表格不支持，需先另存为 `.xlsx`。
- `merge` 把每个 sheet 的**第一行当表头**；没有表头的纯数据表会被当成表头；多级表头不特殊识别。
- `clean` 的重复行判定是**整行 trim 后完全一致**；按单列去重需要自己先处理。
- 不做透视、不做分组统计、不做跨表公式、不做格式校验。
- 缺 `python3` 或 `openpyxl` 时会明确打印安装命令（`python3 -m pip install openpyxl`），不会静默失败。
- 不联网、不上传表格，全部在本机处理。

## PDF

# PDF 工具箱

**一句话**：PDF 合并 / 按页拆分 / 压缩 / 整页文字水印 / 提取文本 / 导出内嵌图片。

## 什么时候用

用户提到「PDF 工具箱」，或要求 PDF 合并、拆分、压缩、加水印、提取文字、导出图片时使用。
适合批量、可重复、需要留下可核对产物的场景；一次性手工点选不是必须用它。

## 怎么调用

```bash
<cli 路径> --help
```

```bash
# 看效果（自造样例，不碰用户文件）
<cli 路径> --demo

# 统一形式：<子命令> [动作] --input <文件或目录> [--out <目录>] [--json]
<cli 路径> merge --input a.pdf,b.pdf --out out
<cli 路径> split --input report.pdf --out out
<cli 路径> split every-n --n 2 --input report.pdf
<cli 路径> compress --quality 60 --input big.pdf
<cli 路径> watermark --text "内部资料" --input a.pdf
<cli 路径> extract-text --input a.pdf
<cli 路径> extract-images --input a.pdf
```

也可以写成 `<cli 路径> pdf merge ...`（`pdf` 前缀可省略）。

## 各动作要点

| 子命令 | 可调选项 | 说明 |
|---|---|---|
| `merge` | `--input` 可重复或逗号分隔 | 至少 2 个 PDF；按给定顺序合并 |
| `split` | `--n N` 或动作 `every-n` | 默认按页；每 N 页一份 |
| `compress` | `--quality 1-95`、`--dpi 36-600` | 图片降采样 + JPEG 重编码 + 字体子集化 |
| `watermark` | `--text`（必填）、`--fontsize`、`--opacity 0.01-1` | 整页平铺文字水印，中文可用 |
| `extract-text` | — | 每页一个 UTF-8 `.txt` |
| `extract-images` | `--min-bytes N` | 导出页面内嵌图片原始字节 |

## 边界（必须向用户说清）

- **能**：合并、按页/每 N 页拆、有图 PDF 的压缩、文字水印、文本提取、内嵌图片导出；单文件、多文件、单层目录批量。
- **不能**：OCR（扫描件提不出文字）、解密/绕过受保护 PDF、编辑文字或版式、图片/Logo 水印、递归子目录。
- **不改输入文件**：只写输出目录（默认 `<输入目录>/_输出`）；同名自动加 `-1`/`-2`，不覆盖。
- **压缩不保证更小**：没有图片或已高度压缩时可能压不动，会如实报告「未变小」，不要承诺体积下降比例。
- **水印有文本层**：水印文字可被提取，不能当作防复制手段。
- 缺 python3 / PyMuPDF 时命令会明确报错并给安装命令，不会静默失败。先可用 `--probe` 检查环境。
- 退出码：`0` 成功 / `2` 参数或输入错误 / `3` 依赖缺失 / `4` 执行失败。给程序用 `--json`。

## 汇报建议

执行完把产物路径与核对数据（合并页数、拆分文件数、压缩前后字节数、抽出的 txt/图片数量）一并告诉用户；
不要说「已压缩」而不给前后体积，也不要在未跑通时声称成功。
